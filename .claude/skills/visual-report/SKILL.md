# 한눈에 읽히는 보고 문서

**기준 문서**: `D:/경추ROM/1_선실측(현재 방식)/CoCoChuna_경추ROM_선실측_직접각_면각_비교_V0.1_20261015.pdf` — 사용자가 «완전 잘 읽힌다 · 지금이 딱 그런 느낌»이라고 한 양식(10-15). 새 문서는 이것과 같은 결로 만든다.
**목적**: 읽는 사람이 **처음 30초 안에 결론을 알고, 그림 하나씩 보며 납득**하게 한다. 근거는 다 넣되 앞에 세우지 않는다.

## 1. 뼈대 (이 순서를 지킨다)

1. **제목 + 한 줄 출처** — `날짜 · 프로젝트 · 자료 범위(예: Link 시험 측정 199건)`
2. **한 줄 결론 상자**(`key()`) — 답과 그 숫자. «~이다»로 끝낸다. 배경 설명 금지
3. **무엇을 비교하나** — 정의는 짧은 표(행 = 계산 / 쓰는 것 / 담는 것). 한 문장으로 «언제 같고 언제 다른가»
4. **그림 절** — 절마다 `h2` → `how()`(읽는 법 상자) → `figure()` → 그림이 말하는 것 1~2문장. 순서는 아래 그림 순서표를 따른다
5. **정리 표** — `항목 | 판단` 두 칸. 판단은 «데이터로 보면 ~하다» 수준(설득조 금지)
6. **부록 숫자 표** — 모든 숫자는 여기 한 번. 본문 그림과 같은 숫자를 또 표로 쓰지 않는다
7. **맨 끝 작은 글씨**(`foot()`) — 자료 출처 · 검산 방법과 결과 · **확인하지 않은 것** · 이 문서의 범위 밖

## 2. 그림 순서 (필요한 것만 고른다)

| 순서 | 그림 | 도구 | 무엇을 보여 주나 |
|---|---|---|---|
| ① | 두 값 나란히 막대 + 오른쪽 차이(초록/빨강) | `paired_bars` | 평균으로 본 큰 그림 — 3초 안에 «거의 같다/다르다» |
| ② | 한 줄 점 그래프(분산) | `strip` | 표본 하나하나가 어디 있나 · 기준 띠 · 중앙값 막대 · 줄마다 `n건 · 1° 안 %` |
| ③ | 구간 비율 100% 막대 | `stacked` | «몇 %가 몇 도 안인가» |
| ④ | 검증/원인 산점도 | 직접 SVG | 점 무리마다 **번호 붙은 이름**(① ② ③)과 한 줄 설명을 그림 안에 |
| — | 사진 대비 | `pair` + `pins` | «보이는 것 vs 실제»를 나란히 · 핀은 대상 **옆**에(글자 가리지 않게) |
| — | 원리 그림 | 직접 SVG | 반드시 «원리 그림(실측 아님)»이라고 적는다 |
| — | 순서 · 수칙 | `cards` | 3~4칸 카드 |

★**점 그래프를 그냥 내밀지 않는다**(10-15 «읽는 게 눈에 확 안 들어온다»). 점 그래프에는 반드시:
- 그림 **위** `how()` 상자: «점 하나 = 한 건 · 초록 띠 안이면 ~ · 검은 막대 = 중앙값»
- 기준 띠(±허용치)를 초록으로 칠하고 띠 위에 «±1° 안» 글자
- 축 양쪽 방향 글자 «← 직접 각이 더 작다 / 더 크다 →» (부호를 해석하게 만들지 않는다)
- 무리마다 이름 · 건수 · 한 줄 해석을 그림 안에

## 3. 보기 규칙

- 색은 역할마다 하나: 좋음 `GREEN` · 약간 `LGREEN` · 주의 `AMBER` · 나쁨 `RED` / 비교 두 값 = `GREY`(지금 값) vs `BLUE`(새 값) / 다른 종류 무리 = `ORANGE`
- 값은 막대 끝에 숫자로. 축 눈금과 숫자를 둘 다 빽빽하게 넣지 않는다
- ★**작은 차이를 키워 그리지 않는다** — 실제 비율 그대로 그린다. «작아서 안 보인다»가 곧 결론이면 그 모습을 보여 주고 숫자를 옆에 적는다. 10-15에 1.2m 선의 옆 어긋남(13mm)을 20배로 그렸다가 «오히려 오해만 산다»는 지적을 받았다(실제보다 크게 틀어진 것처럼 보인다). 차이를 꼭 견주어야 하면 허용치 기준선이 있는 막대로 보인다
- 띠·기준과 캡션 숫자가 서로 맞는지 본다(10-15: 띠 중심을 틀리게 잡아 «모두 ±1mm 안» 캡션과 어긋났다)
- 맑은 고딕 · A4 · 문장은 해라체 · 25자 안팎 짧은 문장 · 한 문단 3문장 이하
- 사람 얼굴이 나온 프레임은 쓰지 않는다

## 4. 글 규칙

- **실측 / 계산 / 원리를 섞지 않는다** — 계산이면 «(계산)», 원리면 «원리 그림(실측 아님)»
- 단정·설득조 금지(«~가 맞다», «~해야 한다»). 숫자와 «데이터로 보면»으로 말한다 — [[tone-korean-polite]]
- 모르는 것은 추측으로 메우지 않고 foot에 «확인하지 않은 것»으로 적는다(예: «판마다 무엇을 쟀는지 CSV에 없다»)
- 사용자 용어를 쓴다: 벽면UI · 컨트롤러UI · 미간점 · 턱끝점 · 이주점(Gl/Gn/Tr 금지) · 버튼 설명은 «A : 리셋» 꼴

## 5. 만들기

```python
import sys; sys.path.insert(0, r'C:/UnityProjects/GuideChuna/.claude/skills/visual-report')
from report_kit import *
body = (title('…', '2026-10-15 · CoCoChuna 경추ROM … · 자료 범위')
        + key('… <b>핵심</b> …')
        + h2('1. …') + how('…') + figure(paired_bars(items, '면 각 (지금 쓰는 값)', '직접 각', 100), '캡션')
        + … + foot('자료 … 검산 … 확인하지 않은 것 …'))
save(body, '문서 제목', out_dir, 'CoCoChuna_경추ROM_<주제>_V0.1_<yyyymmdd>')   # → out_dir/<이름>.png 캡처 + D:/<이름>.pdf · .html
```

- 생성기는 세션 scratchpad에 두고 돌린다. 예시 = `examples/`(비교 문서 · 정밀도 시험 · 사용 매뉴얼)
- ★**저장 전에 캡처(`<이름>.png`)를 반드시 눈으로 본다** — 글자 겹침 · 핀 위치 · 띠/캡션 불일치를 이걸로 잡았다. 필요한 부분은 ffmpeg `crop`으로 확대해 본다
- PDF 쪽수 확인: `re.findall(rb'/Type\s*/Page[^s]', pdf)` 개수
- 함정: Chrome `--print-to-pdf`를 bash에서 `"D:\\$N.pdf"`로 쓰면 `$N`이 안 풀린다 → `save()`를 쓰거나 `"D:/$N.pdf"`
- matplotlib 없음 → 그림은 SVG 문자열로 직접. 새 그림 꼴이 필요하면 `report_kit.py`에 함수로 더한다
- 문서는 **D 드라이브 파일**로 낸다(Claude Docs 아님) — [[docs-as-local-files]]
