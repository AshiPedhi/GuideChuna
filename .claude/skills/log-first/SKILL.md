# 로그 먼저

**두 가지 규칙이다. 2026-09-07에 하루를 통째로 날리고 만들었다.**

1. ★**원인 검증에는 반드시 로그를 확인한다.** 화면 증상만 보고 원인을 말하지 않는다.
2. ★**기능을 추가·변경할 때는 위험한 자리에 로그를 먼저 심는다.** 나중에 심으면 이미 늦다.

---

## ① 원인 검증 — 말하기 전에 읽는다

```bash
# 전체 흐름
grep -a "태그" "/c/Users/USER/AppData/Local/Unity/Editor/Editor.log" | tail -40

# 여러 줄 로그는 -A 로 이어 본다
grep -a -A 1 "태그" "/c/Users/USER/AppData/Local/Unity/Editor/Editor.log" | tail -20
```

- ★**`grep -a` 필수.** 로그에 바이너리가 섞여 있어 `-a` 없으면 "binary file matches"만 나온다.
- 경로는 `%LOCALAPPDATA%\Unity\Editor\Editor.log`. 이전 판은 `Editor-prev.log`.
- ★**Play를 다시 돌려 달라고 하기 전에 이미 있는 로그부터 읽는다.** 사용자가 이미 돌렸을 수 있다.

### 이걸 안 해서 생긴 일 (2026-09-07)

경추ROM 실습 정보창이 "안 따라간다"는 증상에 대해 **회전 공식을 다섯 번 갈아 끼웠다.**
그러는 동안 로그에는 이미 이 줄이 24번 찍혀 있었다:

```
[실습표시·추종] 머리각 0.0도 · 머리자리 (0.003,1.171,0.332)
```

**머리 뼈가 회전도 위치도 전혀 안 바뀌고 있었다.** 즉 내가 읽던 신호가 죽어 있었고,
그걸 읽는 어떤 공식도 맞을 수가 없었다. **로그 한 줄이 다섯 번의 왕복을 대신할 수 있었다.**

### 단정하기 전에 스스로 묻는 것

- 이 원인을 **로그에서 봤나**, 아니면 화면을 보고 **짐작했나**.
- 로그가 없으면 — **지금 심을 수 있나**(아래 ②).
- ★"씬에 X가 있으니 원인은 X다"는 **추론이지 실측이 아니다.**
  09-07에 "씬에 음수 스케일 167개가 있으니 이게 원인"이라고 했다가
  "그 사슬이 음수인지는 안 봤잖냐"고 바로 잡혔다. **사슬을 직접 곱해 봐야 실측이다.**

## ② 기능을 고칠 때 — 위험한 자리에 로그를 심는다

**"조용히 틀리는" 자리를 만들 때는 그 자리가 스스로 말하게 만든다.**
이 프로젝트에서 조용히 틀리는 자리는 정해져 있다.

| 위험한 자리 | 심을 로그 |
|---|---|
| **런타임에 컴포넌트를 붙인다** | `붙었다 — 참조 A 있음/★없음` (Awake에서 1회) |
| **이름·경로로 무언가를 찾는다**(`Find`·`FindDeep`) | 못 찾으면 **경고**. 규칙 8 — 이름 매칭은 조용히 죽는다 |
| **게이트가 여러 개다**(안 그림·안 넘어감·안 잡힘) | ★**막은 게이트를 이름으로** 찍는다. 통과하면 저절로 조용해지게 |
| **좌표·회전·축을 계산한다** | 입력값과 결과를 **같이** 찍는다. 하나만 찍으면 어디서 끊겼는지 모른다 |
| **모드·상태로 갈라진다**(실습/실측) | 갈림길에서 어느 쪽으로 갔는지 |
| **씬 값이 코드 기본값을 이긴다**(규칙 7) | 실제로 먹은 값을 찍는다 |

### 로그 모양 — 세 가지 틀

**ⓐ 붙었다 (Awake 1회)** — "안 붙은 것"과 "붙었는데 안 도는 것"은 화면에서 똑같아 보인다.
```csharp
ChunaLogger.Log($"<color=cyan>[태그] 붙었다 — 드라이버 {(driver != null ? "있음" : "★없음")}</color>");
```

**ⓑ 막은 이유 (자기 침묵)** — ★**막힐 때만** 말하고, 잘 돌면 한 줄도 안 남긴다.
```csharp
private float nextSilentLog;
private string lastSilentReason;

private void ReportSilent(string reason)
{
    if (reason == lastSilentReason && Time.unscaledTime < nextSilentLog) return;
    lastSilentReason = reason;
    nextSilentLog = Time.unscaledTime + 2f;
    ChunaLogger.LogWarning($"<color=orange>[태그] 안 그린다 — {reason}</color>");
}
```
게이트마다 **다른 문장**을 넣는다. `ReportSilent("경추ROM 시나리오가 아니다")` 처럼.
통과하는 자리에서 `lastSilentReason = null;` 로 풀어 준다.

**ⓒ 따라가나 (주기 + 변화)** — 값이 **안 변하는 것도 정보다.**
```csharp
// ★변화가 없어도 2초마다 찍는다. 변화가 있을 때만 찍으면
//   "아예 안 변한다"는 사실이 로그에 한 줄도 안 남아 원인을 못 가린다.
if (!moved && Time.unscaledTime < nextProbeTime) return;
nextProbeTime = Time.unscaledTime + 2f;
```
★**입력·중간값·결과를 한 줄에 나란히** 둔다. 그래야 어디서 끊겼는지가 한 눈에 갈린다:
```
[태그] 입력 24.0도 · 중간 (0.00,1.17,0.33) · 목표 (…) · 실제 (…) · 부모 홀더
```
- 입력이 안 변함 → **소스가 죽었다**(내 계산 문제 아님)
- 입력은 변하는데 목표가 안 변함 → **내 계산이 틀렸다**
- 목표는 변하는데 실제가 안 변함 → **대입이 안 먹는다**

### 지표를 잘못 잡지 않기

★**섞인 값을 재면 로그가 거짓말을 한다.** 09-07에 `Vector3.Angle(root.up, Vector3.up)`을 찍었는데
그건 **강체 기울기와 빌보드 피치를 섞어** 재는 값이라, 중립인데 33도가 나왔다.
→ **재려는 그것 하나만** 재는 값을 고른다. 애매하면 원천 값(두 점의 차 같은)을 그대로 찍는다.

## ③ 계산을 제약할 때 — <b>무엇을 지우는지</b> 적는다

★★**`ProjectOnPlane` · `.y = 0` · 클램프 · `Abs` · 정규화는 전부 <b>정보를 버리는</b> 연산이다.**
"원하는 것만 남긴다"가 아니라 "**나머지를 못 보게 만든다**"로 읽어야 한다.

**제약을 한 줄 쓸 때마다 주석으로 한 줄 답한다: <b>이건 무슨 변화를 지우나.</b>**

```csharp
// 지움: 축 방향 성분 → 그쪽으로 아무리 움직여도 결과가 안 바뀐다. 그래도 되나?
Vector3 flat = Vector3.ProjectOnPlane(v, axis);
```

### 이걸 안 물어서 생긴 일 (2026-09-07)

머리 위 정보창을 **"y축 둘레로만 돌린다"**로 만들면서 `toCam.y = 0`을 썼다.
그런데 판이 환자 머리를 따라 **아래로 딸려 내려갈 때** 헤드셋과의 직선 변화는
**거의 전부 그 y 성분**이었다. 내가 손으로 지운 그 성분이다.
→ 아무리 내려가도 겨눔이 안 바뀌었고, 화면에서는 "이동에 반응을 안 한다"로 보였다.
★**사용자가 원인을 짚어 줄 때까지 나는 그런 상황이 있다는 것 자체를 몰랐다.**
  배제한 게 아니라 무지였다. **제약 = 삭제**라고 읽었으면 그 자리에서 걸렸다.

### 만들기 전에 적는 <b>의존 목록</b>

새 표시·판정을 만들 때, 코드보다 먼저 두 줄을 적는다.

1. **이 결과는 무엇이 바뀌면 바뀌어야 하나** (예: 판 자리 · 카메라 자리 · 머리 기울기)
2. **그 각각이 내 계산에 실제로 들어오나** — 한 줄씩 짚는다

★목록에 있는데 계산에 안 들어오는 항목이 있으면 **그게 곧 버그다.**
09-07의 `toCam.y = 0`은 이 표를 한 번만 그렸어도 걸렸다:

| 바뀌어야 할 입력 | 내 계산에 들어오나 |
|---|---|
| 카메라가 좌우로 이동 | ✅ |
| 카메라가 위아래로 이동 | ❌ **y를 지웠다** |
| 판이 아래로 딸려 내려감 | ❌ **같은 이유** |
| 머리 기울기 | ✅ (up으로) |

★그리고 그 목록의 각 항목은 **②의 ⓒ 로그로 그대로 옮긴다.**
"입력이 바뀌었는데 결과가 안 바뀐다"를 로그가 잡아 주는 게 이 표의 런타임 판이다.

## 함정

- ★★**릴리스 빌드에서는 `ChunaLogger.Log`·`LogWarning`이 통째로 잘린다**(`Conditional`).
  없는 로그를 보고 "그 분기 안 돌았다"고 단정하면 틀린다(09-03 오진).
  기기 로그가 필요하면 **Development Build**로.
- 콘솔이 cp949라 파이썬을 쓸 때는 `PYTHONIOENCODING=utf-8`.
- Editor.log는 RenderStreaming이 계속 밀어내므로 **바로 읽는다.**
- 로그를 심고 나면 **사용자에게 무엇을 보면 되는지 한 줄로 알려 준다.**
  "돌려 보세요"가 아니라 "`[태그]` 줄만 주세요"라고 말한다.

## 정리하기

증상이 해결되면 **진단 로그를 지울지 남길지 정한다.**
- 남긴다: 게이트가 여러 개라 또 막힐 수 있는 자리(ⓑ)
- 지운다: 한 번 확인하고 끝난 계산 추적(ⓒ)
★남길 때는 **자기 침묵**이어야 한다. 잘 도는 동안 로그가 쏟아지면 다음 사람이 진짜 신호를 못 찾는다.
