## 왜 있는가

2026-09-01에 이 부호를 **추론으로 맞히려다 다섯 번 왕복했다.** 한 면을 고치면 다른 면이
딸려 틀어졌다. 사용자가 "횡단면 앞뒤만 바꾸라니까 왜 시상면 위아래가 바뀌냐"고 지적한 게
그 구조 때문이었다.

교육 쪽 `CervicalRomDriver.AxisOf`에도 같은 이력이 적혀 있다 —
`// ★부호는 Play에서 눈으로 확인해 뒤집었다(2026-08-24)`.
**이 부호는 머리로 못 맞힌다. 재야 한다.** 이 스킬이 그 자리다.

## 무엇을 재는가

환자가 앉아 있고 **앞 = +Z · 오른쪽 = +X · 위 = +Y**인 기준 상황을 놓고,
각 방향에서 각도기의 **+30° 지점이 실제로 어디를 향하는지** 계산한다.

| 방향 | +30°가 가야 할 곳 |
|---|---|
| 굴곡 | 환자 앞(+Z) — 숙인다 |
| 신전 | 환자 뒤(−Z) |
| 우측굴 · 우회전 | 환자 오른쪽(+X) |
| 좌측굴 · 좌회전 | 환자 왼쪽(−X) |

거기에 **횡단면 0°가 환자 앞을 보는지**를 따로 본다. 회전만 `Torso.forward`를 0°로 쓴다.

## 2026-09-01 검증 결과 (16조합 전수)

**전부 맞는 조합은 두 개뿐이고, 둘 다 `refFwd = Cross(refRight, up)` · 짝은 `base`다.**

```
OK  마주  l-r  cross  base
OK  뒤    r-l  cross  base
```

갈리는 건 **시술자가 어디 서느냐 하나**뿐이다. 그게 `refRight`의 부호를 정한다.

## 여기서 나온 규칙

- ★**`refUp`은 언제나 월드 수직이다.** 외적으로 뽑으면 `refFwd`를 뒤집을 때 딸려 뒤집혀
  시상면 위아래가 같이 바뀐다. 09-01에 실제로 밟았다.
- ★**`refFwd`를 뒤집으면 측굴·회전 네 방향이 같이 깨진다.** 관상면 축이 `axFwd`라서다.
  표의 `-cross` 줄이 전부 그렇다.
- ★**횡단면 0°만 바꾸고 싶으면 `Torso.forward`만 뒤집는다.** 관상면 축은 `axFwd`를 따로
  쓰므로 서로 안 딸려 온다. 그래서 이 둘은 <b>다른 손잡이</b>여야 한다.
- ★**짝을 통째로 맞바꾸면(`swap`) 여섯 방향이 전부 깨진다.** "3면 다 이상하다"는 신고를
  짝 문제로 읽으면 안 된다 — 그건 보는 면·라벨 문제일 수 있다.
