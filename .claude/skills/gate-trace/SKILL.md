# 게이트 추적

**읽기 전용이다.** 아무 파일도 고치지 않는다.

```bash
PYTHONIOENCODING=utf-8 "C:/Users/USER/AppData/Local/Python/pythoncore-3.14-64/python.exe" \
  .claude/skills/gate-trace/trace.py <플래그이름> [--file=파일이름조각] [--depth=3]

PYTHONIOENCODING=utf-8 "C:/Users/USER/AppData/Local/Python/pythoncore-3.14-64/python.exe" \
  .claude/skills/gate-trace/trace.py --scan=<파일.cs> [--min=3]
```

- 이름만 주면 그 이름의 **조건식 정의를 전부** 찾는다. `on`처럼 흔한 이름은 `--file=`로 좁힌다.
- `--scan=`은 그 파일에서 **항이 여러 개인 조건식**을 목록으로 뽑는다. 이름을 모를 때 먼저 돌린다.
- 조건식이 아니라 그냥 플래그를 줘도 된다. 그 경우 **켜는 자리·끄는 자리·씬 값**만 뽑는다.

## 왜 있는가

2026-09-08 하루에 **게이트를 덜 푼 사고가 4건** 났고, **그중 3건이 같은 파일 같은 조건식**이었다.

사용자 지적이 매번 같은 모양이었다 —
> "강체 생성하면 강체 기둥 보이게 하라고 했는데 **왜 굴곡 파지 해야 그때부터 보이냐**"

`bool on = showRigidBody && rigidReady && frameReady && !gaugeForceHidden`에서
`frameReady`가 **양손 파지 틀**이라야 참이 되는데, 그걸 안 보고 다른 항만 풀었다.
`CervicalRomRealityMeasure.cs:3976`에 그 이력이 주석으로 남아 있다.

**전부 정적으로 잡히는 종류다.** Play로 잡을 일이 아니었다.

## 무엇을 뽑는가

| | 항목 | 왜 필요한가 |
|---|---|---|
| ① | **항 분해** | `&&`를 최상위에서만 자른다. 삼항·`\|\|`·괄호·부정을 구분한다 |
| ② | **항마다 켜는 자리** | `x = true`가 **어느 메서드 몇 번째 줄**인지. 이게 없으면 영영 안 열린다 |
| ③ | **선언 기본값 ≠ 런타임** | `= true`가 선언이면 켜는 코드가 아니다. **씬 값이 이긴다**(규칙 7) |
| ④ | **씬에 굳은 값** | `showRigidBody`는 코드 `true`인데 씬이 `0`이었다. 코드로 못 끈다 |
| ⑤ | **`#if UNITY_EDITOR`** | 참이 되는 자리가 전부 에디터 전용이면 **빌드에서만 안 켜진다**(규칙 10) |
| ⑥ | **삼항의 산 가지** | 조건이 씬에 굳어 있으면 **어느 가지가 실제로 도는지**가 이미 정해져 있다 |

## 읽는 법

- `★참으로 만드는 자리 없음` = 켜는 코드가 어디에도 없다. **그 게이트는 영영 안 열린다.**
- `[씬값 N]` + `·선언 기본값` = 규칙 7. 코드를 고쳐도 안 바뀐다. **인스펙터에서 바꾸라고 안내한다.**
- `(느슨)` = `||`다. 하나만 참이면 된다 — **막는 항이 아니다.** 여기를 의심하지 않는다.
- `!x  [★거짓이어야 통과한다]` = 부정 항이다. **x를 켜는 자리가 범인일 수 있다.**
- `→ ★<이름>부터 로그를 심는다` = 켜는 자리가 가장 적은 항이다.

## 한계 — ★이걸로 단정하지 않는다

- ★**"켜는 자리가 적은 순"은 <b>추정</b>이다.** 실제 시간 순서가 아니다.
  어느 항이 마지막까지 거짓인지는 **`log-first`로 로그를 심어야** 안다. 이 스킬은 **어디에 심을지**를 정해 준다.
- 메서드 호출 항(`Foo()`)은 **본문을 안 판다.** 이름만 알려 준다.
- 씬은 `TrainingScene`·`lobby` 둘만 본다. **프리팹은 안 본다.**
- ④의 씬 값은 **인스턴스 전부**를 모은다. 같은 필드가 리그마다 다르면 값이 여러 개로 나온다.
- `bool` 타입만 본다. `float` 임계·거리 게이트는 못 본다.

## 순서

★**"왜 안 보이냐"는 `log-first` → `gate-trace` 순서다.**
로그를 먼저 읽어 **어느 표시물인지**를 확정하고, 그다음 그 표시물의 조건식을 이걸로 분해한다.
반대로 하면 엉뚱한 조건식을 판다.

고친 뒤에는 `change-impact`를 돌린다. 게이트를 푸는 건 **표시 변경**이라 공유 컴포넌트면 13개 술기에 번진다.
